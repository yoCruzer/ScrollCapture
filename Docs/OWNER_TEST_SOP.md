# ScrollCapture 人工真机测试 SOP

日期：2026-11-26。适用修复版 `2ec9950`。

## 「预览」首屏故障复测

先退出旧版，解压本机架构的修复包。在系统「预览」打开上次失败的长图，以实际大小显示（⌘0），确认上下滚动能看到不同行，再回到起点。只框选图片正文，点“开始滚动截图”。连续滚动几个小段，核对拼接次数、结果首行和末行，保存 PNG。若仅保存首屏，记录浮窗原文和确认高度即可，无需分享图片。

开发复测可用 `swift Scripts/make-preview-fixture.swift /tmp/scrollcapture-article.png` 生成 760×6000 白底编号长图（输出文件须为新文件），在「预览」实际大小下复验。完整结果需逐像素对照原图，并有带白边、重绘和真正丢失重叠的反例。额外浏览器/原生应用流程如下。

建议先完成 A–F，约 20–30 分钟；G 按实际使用场景补充，H 是可选自动诊断。每项记“通过 / 失败 / 未测试”，遇到失败即可反馈，不必勉强做完所有项目。

## 准备（2 分钟）

1. 用 Finder 的“前往 → 前往文件夹”（⇧⌘G）打开：

   `~/Development/Projects/ScrollCapture/build/`

   双击 **ScrollCapture.app**。不要打开旁边的 `ScrollCapture-303c331.app` 旧版。不要重新构建；重建可能导致权限需要重新授权。
2. 准备一个仅本地保存的测试目录，例如仓库下 `artifacts/owner-20261120/`；该目录已被 Git 忽略。不要把真实截图、窗口标题或私聊上传到公开 PR。
3. 打开 Safari，用 ⌘O 选择仓库里的 `Fixtures/browser.html`。这是带 `ROW 000…` 行号、彩色横条和右侧纹理的非敏感测试页，无需登录。
4. 浏览器缩放设为 100%（⌘0），测试期间保持目标窗口尺寸、显示器和缩放不变。将页面滚到彩色正文开头，让框选起点落在一个清楚可辨的行号上。不要框入顶部说明、浏览器工具栏或滚动条；保留右侧纹理有助于定位。
5. 若点“选择窗口…”能读到窗口列表，权限正常。只有失败时才按 [权限操作](BUILD_AND_VALIDATE.md#一次集中权限操作)恢复。手动截图不需要辅助功能权限。

## A. 第一次打开是否看得懂（1 分钟）

操作：看主窗口；打开右上角“使用帮助”，再关掉；点“选择窗口…”，选 Safari 中的合成测试页，再点“预览并选择范围”。

通过标准：

- 能理解左侧三步和当前下一步；预览显示的是你选择的窗口。
- 文字和按钮可读，没有被裁切、重叠或挤出窗口。
- 即使功能正常，但你找不到入口或不理解文案，也请记为“体验问题”，写下卡住的位置。

## B. 普通区域截图、保存与复制（3 分钟）

操作：

1. 在预览里拖选一块正文，包含几行完整行号和右侧纹理。
2. 点“截取所选区域”。记下显示的宽×高。
3. 切换“适合窗口 / 100%”，检查边缘、文字和内容。
4. 点“保存 PNG…”，保存为 `B-region.png`；用“预览”打开。
5. 点“复制完整结果”，打开 macOS“预览”，使用“文件 → 从剪贴板新建”（通常为 ⌘N），检查复制的图片。

通过标准：保存和复制都只包含所选区域，尺寸一致，边界和文字正确；没有变成整窗、空白或其他窗口。100% 可查看原始细节，适合窗口只改变显示大小。

附加：点“新建截图”→“保留截图”，结果应保留；再点新建并确认放弃，应回到第一步。重新预览后应仍能拖选，不能被上次的100%模式影响。

## C. 手动滚动长图（4 分钟，核心必测）

操作：

1. 新建截图；Safari回到刚才选定的正文起点，重新预览并框选正文。
2. 记住选区第一条完整行号，例如 `ROW 005`；点“开始滚动截图”。
3. 切回目标窗口，鼠标放在正文内。每次向下滚约选区高度的 **1/4**，停约 **1 秒**；至少做 **4 次**。大部分旧内容仍应留在视野里。
4. 观察小浮窗的长度和“次拼接”是否增加。若未增加或暂停，先记下提示，不要连续猛滚。
5. 记住末尾完整行号，点浮窗“完成并预览”；保存 `C-manual.png`。
6. 在“预览”以100%逐段检查起点到终点，尤其是中间衔接和标有“合法重复内容”的行。

通过标准：

- 至少3次成功拼接，结果从你选择的当前画面开始，首尾与实际采集范围一致。
- 行号连续，没有跳号、重号、横向错位、半行、白缝或明显模糊；有意重复的文字在各自行号处仍保留。
- 小浮窗没有出现在导出图中；采集过程不反复抢走目标窗口焦点。
- 结束采集只表示你结束了本次范围，不应显示“已确认到达文档底部”。

## D. 暂停与缺口恢复（4 分钟，核心必测）

先新建一次独立采集，按C慢滚到至少3次拼接。

**主动暂停：**点浮窗“暂停”，记下确认长度；静止2秒，长度应保持不变。点“继续采集”，回目标正文慢滚一次，应可继续增加。

**故意制造缺口：**记下当前正文中一条行号及确认长度，然后快速向下跳超过一个选区高度（例如按Page Down或大幅滚动）。

- 如果提示“缺少可靠重叠/位移不唯一/需要回滚”，应立即冻结长度；两秒内的新帧可重新匹配，窗口过后到达的新帧须暂停。记录暂停时长度；此前若已确认了中间画面，可以比操作前增加，但暂停后必须冻结。
- 向上滚回刚才记住的内容，使其重新进入选区；如已暂停则点“继续采集”，随后小步向下滚，检查能否恢复。完成并保存 `D-recovered.png`，按C检查行号。
- 若无法恢复，点“完成并预览”：应仍能保存已确认部分，并明确提示局部结果/未确认尾部。
- 若快滚仍被连续正确采集，没有触发暂停，记录“未触发”，不能据此判恢复通过。不要反复尝试到影响正常操作。

通过标准：缺口不会静默生成看似完整的错图；暂停保留已有范围；能回滚恢复，或明确保留可保存的局部结果。若结果漏行/重行却显示成功，直接记失败。

## E. 裁剪与放弃保护（3 分钟）

操作：

1. 对已完成结果记下原高度H，展开“裁掉顶部 / 底部”，输入顶部10、底部20，点“应用裁剪”。
2. 结果高度应变为 **H−30**，宽度不变；保存 `E-trimmed.png`，检查顶底确实裁去对应内容。
3. 输入负数，或顶部与底部总计超过剩余高度；应不能应用，已有结果仍在。恢复输入0。
4. 点“新建截图”并选择保留，确认结果没有消失。截图已保存后，再确认放弃，开始下一张。

通过标准：裁剪尺寸正确，无效输入不破坏结果，放弃前有明确确认。当前裁剪没有撤销；先保存原图再裁。

## F. 退出重开与第二次采集（2 分钟）

操作：保存需要的结果后，用⌘Q退出；重新打开同一个 `build/ScrollCapture.app`，再读窗口列表，做一次小区域截图。

通过标准：能正常退出、启动，旧浮窗不残留，同一个二进制的录屏授权仍有效，第二次截图正常。临时采集结果不会在重启后恢复，所以先保存。

## G. 真实使用场景补测（建议至少选1种）

在你日常会使用的应用中，拿**公开文章或自己准备的非敏感测试内容**重复B和C：

| 场景 | 重点检查 | 记录 |
|---|---|---|
| Safari / Chrome长文章 | 排除固定导航；文字、图片交界是否漏接 | 应用版本、通过/失败 |
| 飞书 / 微信等聊天应用（已有且可用时） | 用自备测试消息，保留相同文字的不同消息；排除侧栏和输入框 | 未安装/无安全样本就记未测试 |
| 原生列表或文档 | 小滚动、暂停、完成后的首尾 | 应用名称、通过/失败 |

设备与长图检查可后补：Retina/不同显示器、采集中调整窗口尺寸、超8MP分片。窗口几何改变时应安全停止或要求重新框选；不要期待跨显示器继续无缝拼接。超8MP时应显示“保存全部分片”，产生有序PNG和manifest，不能只复制首片却声称整图成功。短截图通常不会触发分片，无需为首轮验收强行达到阈值。

## H. 自动滚动诊断（可选，已知未通过）

手动核心验收可以先完成。若你愿意协助复现自动问题，另开一轮采集：

1. 在目标正文先完成至少3次手动拼接，记下拼接数与当前行号。
2. **先点击目标正文，使目标应用成为前台**，然后打开浮窗“…”→“尝试自动滚动（实验功能）”。需要时为实际ScrollCapture开启辅助功能权限。
3. 在3秒内仅把鼠标移回正文，保持约8秒，不点击、不按键、不滚轮。
4. 记录是否真正向下滚动、拼接数增加多少，以及停止提示原文。没滚动就记“自动失败”，无需反复重试或重置权限。
5. 若确实滚动，手动滚轮或切换应用，应立即停止自动输入。完成并检查导出图是否连续。

静止、长度不变或只出现“画面已定位”都不算自动通过。原生受控窗口和浏览器都需要实际新增多视口、正确输出及接管停止证据；单次尝试不能关闭F06未完成项。
